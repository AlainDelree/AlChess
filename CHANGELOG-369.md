# Changelog — Issue #369

## Correctif #368 — l'interface ne démarrait plus

Cause : `nicsoft/web/static/app.js` enregistrait un `socket.on("lichess_network_status", ...)` au premier niveau du script, AVANT la déclaration `const socket = io();` (plus bas dans le même fichier) — `const` étant en zone morte temporaire jusqu'à son exécution, ceci levait `ReferenceError: Cannot access 'socket' before initialization` dès le chargement de la page, interrompant toute l'initialisation JS (`#startup-overlay` ne se masquait donc jamais, dans un vrai navigateur comme dans les tests Playwright). Rapport #368 à tort attribué à une limite de l'environnement de test : confirmé régression par comparaison `avant-368`/`#368` (12 réussis → 13 erreurs sur `test_smoke_e2e.py`).

- `nicsoft/web/static/app.js` : ce `socket.on(...)` déplacé après `const socket = io();`, à côté des autres gestionnaires `lichess_*`.
- Second bug trouvé au passage (même fichier, même commit #368) : `_applyBoardBadge()` masque génériquement toute `.board-warning-banner` selon `!_boardError` — `#lichess-network-banner` réutilise cette classe pour le style mais dépend du réseau, pas de l'échiquier ; la boucle générique écrasait donc `_applyLichessNetworkState()`. Sélecteur corrigé en `.board-warning-banner:not(#lichess-network-banner)`.
- `nicsoft/tests/e2e/test_issue368_lichess_network_e2e.py` (jamais exécuté avant cette issue) : corrigé deux bugs de test — `_declencher_evenement_socket_client` ne retrouvait plus le gestionnaire réel une fois détaché (`socket.off`) ; repli sur les callbacks capturés dans `window['__real368_' + event]`. Sélecteur du bouton « Retour » élargi à `:visible` (le premier `data-action="back_menu"` du DOM, dans le bandeau « partie en cours », reste caché par défaut).
- Nouveau garde `nicsoft/tests/e2e/test_issue369_startup_js_guard.py` : vérifie, dès le chargement, l'absence d'erreur JS et la disparition de `#startup-overlay` — aurait détecté cette régression directement (confirmé en relançant contre la version cassée). Lance son **propre** serveur dédié (comme `server_url`, mais jamais celui de session) : y connecter un second client socket.io cassait en cascade tous les tests e2e suivants (le serveur suppose un seul client à la fois — `_app_state`/queues globales).
