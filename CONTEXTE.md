# AlChess — Contexte projet

Briefing CCL. Seuls les ~4000 premiers caractères sont injectés dans ton prompt ; le reste du fichier reste lisible à la demande (outil de lecture) : garde l'essentiel en haut, le détail plus bas.

## Règles impératives
Elles te sont injectées automatiquement, avec ton prompt, dans la section CONSIGNES (binaires tiers en lecture seule, serveur démarré uniquement avec `ALCHESS_SKIP_BOARD=1 ALCHESS_NO_BROWSER=1`, suppressions de sécurité, pas de push). Ici : si ta tâche change l'architecture, les dépendances, les conventions ou l'avancement, mets à jour ce fichier dans le même commit — l'état réel, pas l'historique (l'historique va dans `CHANGELOG-<N>.md`).

## Projet
**AlChess** (ex-NicLink) : app Python/Flask-SocketIO reliant un échiquier Chessnut USB (ou virtuel) à une UI web pédagogique. Front vanilla JS. Ubuntu + support Windows. Local `~/NicLink/` (venv) ; GitHub public AlainDelree/AlChess. Dév : Alain (non-dev).

## Architecture (`nicsoft/`)
- `niclink/` : `hid_backend.py` (USB hidapi pur), `driver.py` (thread FEN, LEDs, bip), `virtual_board.py`, `nl_exceptions.py`.
- `web/` : `alchess.py` (orchestre), `server.py` (Flask-SocketIO, `_app_state`, détection moteurs), `single_instance.py` (une seule instance à la fois, #320), `launcher.py`, `static/app.js`, `templates/index.html`.
- `core/` : `game_manager.py` (façade ; lanceurs par mode dans `core/game_manager_modes/`, état partagé dans `state.py`), `board_adapter.py`, `config_manager.py`, `ihm_port.py` (port neutre jeu↔IHM).
- `engine/` : `engine_manager` (façade réexportant `move_quality`, `engine_analysis`, `uci_engine`, `engine_detection`, `engine_availability`, `maia_engine`, `rodent_engine`), `players`, `pgn_manager`, `board_utils`, `display`, `analyse`.
- `modes/` (`pedagogique humain exercices retranscription labo opening_explorer`) : `explore_book`, `eco_import`, `llm_explainer` sont des façades réexportant des modules par rôle.
- `config.py` (`APP_DIR` auto), `platform_utils.py`, `utils/` (timing, LEDs, `net_safety.py` : schéma https vérifié avant urllib).

**`_app_state`** : `menu`→`config`/`config_humain`/`retranscription`/`exercices`/`labo`→`connecting`→`playing`/`paused`→`game_over`. **Queues** : `event_queue` Py→nav ; `action_queue` nav→Py (partie) ; `menu_queue` nav→Py (menu).

## Principes techniques
- **ARC-001** : `core/modes/niclink/utils/engine` n'importent jamais `nicsoft.web` ; ils passent par `core/ihm_port.py` (backend branché au démarrage par `nicsoft.web.alchess`, neutre sinon). Garde : `test_no_web_import.py`.
- **USB** : un seul accès ouvert à la fois (`connect()` ferme l'ancien) ; chaque mode appelle `disconnect()` en fin de session ; la présence physique se lit par `hid.enumerate()`, indépendamment de la connexion.
- `board.move_stack` = source de vérité ; `chess.Board(fen)` l'efface → reconstruire depuis l'historique.
- Polling `time.sleep()` ≥ 0.05 s ; threads LED daemon.
- `on_action` : chaque `sendAction({type:X})` JS a son `elif` Python.
- i18n : clé ajoutée **simultanément** dans `fr/en/de.json` (`static/i18n/`) ; allemand incertain → valeur anglaise, jamais absente.
- Tout texte externe (PGN, noms, messages serveur, réponses LLM, Lichess) → `esc()` ou `textContent`, jamais brut dans `innerHTML`. Garde : `test_issue303_html_escaping.py`.
- Aucun secret n'est envoyé au navigateur (clé LLM, jeton Lichess) : le serveur ne renvoie qu'un indicateur de présence (+ indice 4 derniers caractères si valeur ≥ 12). Garde : `test_issue304_security.py`.
- Démarrage serveur (#312) : ne jamais abaisser le niveau du `file_handler` partagé du root logger sans donner à `werkzeug` son propre handler console (sinon `Running on http://...` disparaît, y compris en interactif) ; `server.py:start_server()` affiche toujours l'adresse via `print(..., flush=True)`, indépendamment des loggers. Fixture e2e (`tests/e2e/conftest.py`) : lecture de stdout par fil+queue (jamais bloquante), limite réelle de 20s, arrêt du process par PID si dépassée.
- **Instance unique (#320)** : `alchess.py::main()` appelle `single_instance.resolve_startup()` en tout premier geste. Marqueur `DATA_DIR/server_instance.json` (pid/port/started_at), écrit après choix du port, supprimé à la sortie (`atexit`, seulement si le PID correspond encore). Reconnaissance d'un processus AlChess : PID vivant **ET** ligne de commande contenant `nicsoft.web` (jamais le seul nom du programme — `/proc/<pid>/cmdline` sur Linux, `wmic`/`tasklist` sur Windows, non testé). Partie en cours = requête HTTP locale `GET /instance_status` (route `server.py`, protégée `_require_allowed_host()`) sur l'état vivant (`_app_state` ∈ `single_instance.BUSY_STATES` : `connecting playing paused position_initiale lichess_wait_first_move retrans_playing exercice_running` — exclut menu/config/sélection/labo/opening_explorer) ; état non confirmable → refus par précaution, ancienne instance jamais touchée. Sinon, arrêt par PID exact (SIGTERM puis SIGKILL après 5s, `taskkill /PID` côté Windows — jamais par nom), attente de sortie confirmée (= USB déjà libéré) avant de démarrer. Journal/console : `[NicLink] PID <pid> — port <port>` dès le choix du port. Garde : `test_issue320_single_instance.py`.
- Lichess (`modes/lichess/`, L0 #306, L1 #307, L2a #309, réordonnancement #311) : jeton toujours côté serveur, jamais journalisé ; client (`game_client.py`/`transport.py`/`errors.py`) à transport injectable. Mode jouable depuis le menu (lanceur `core/game_manager_modes/lichess.py`, boucle `modes/lichess/game.py:LichessGame`) : partie amicale contre l'IA Lichess, échiquier physique requis, aucun moteur/aide pendant la partie (fair-play). **Ordre de lancement (#311)** : couleur « aléatoire » résolue localement avant tout appel Lichess ; position confirmée (sans limite de temps, écran « Position incorrecte » + bouton retour menu) **avant** toute création de partie ; **blancs** → partie créée (et 1er coup envoyé) seulement **après** le 1er coup physique de l'utilisateur (pas de partie = pas de contrainte de temps Lichess) ; **noirs** → création immédiate après la position (IA joue aussitôt : son, LED, compte à rebours du 1er coup lu dans `expiration`). Fin inattendue non demandée (aborted/noStart/unknownFinish) → fenêtre explicite (jamais de retour silencieux) avec « Rejouer mêmes réglages »/« Retour au menu ». Plateau logique reconstruit depuis les coups UCI (jamais de maj optimiste) ; pendules par horodatage. Journal : logger `niclink.lichess` en INFO par défaut (pas besoin de `NICLINK_LOG=DEBUG`), jamais le jeton. **Reconnexion automatique (#314)** : lecture vide >1,5s ou module non connecté pendant l'attente de position/1er coup ou en partie → bannière « Reconnexion de l'échiquier… », essais toutes les 2s/30s puis 5s (`hid_backend._connect_lock` protège un seul essai à la fois), jamais de partie créée ni d'abandon automatique avant lecture rétablie ; `hid_backend.py` journalise en INFO chaque ouverture/fermeture/remise à zéro avec son appelant, et throttle l'avertissement de lecture à un par incident. Pas encore : adversaire humain, parties classées. **Orientation côté noirs (#315)** : `set_app_state("position_initiale", ...)` transmet désormais la couleur résolue ; app.js oriente automatiquement l'échiquier de jeu et celui de l'écran de mise en place du point de vue de l'utilisateur via la fonction réutilisable `orientationIsFlipped(color)` (rangée du haut = adversaire, rangée du bas = utilisateur, cohérent avec `lichess_clock`), le bouton de retournement manuel restant disponible. **Correctifs essais réels (#316)** : `LichessGame._submit_move()` porte désormais l'offre de nulle en attente (`offer_draw`) pour que Lichess ne l'annule pas quand on joue (sinon « Nulle refusée » s'affichait à tort) ; évènement dédié `lichess_draw_accepted` quand notre offre aboutit. Écran d'attente du 1er coup des blancs : échiquier de départ + style `.card` (contraste), via `_buildBoardPosInit`/`renderBoardPosInit` généralisées (id/préfixe paramétrables). Pendules : drapeau `_lichessClockRowsSwapped` (app.js), mis à jour par `flipBoard()` et lu par `_lichessRenderClock()`, pour que les pendules suivent les noms au retournement manuel. **Correctifs essai réel #2 (#317)** : écran d'attente du 1er coup (blancs) — panneau explicatif de 3 phrases remplacé par un message court sur une carte verte dédiée (`.card-lichess-ready`/`.lichess-ready-message`), contraste immédiat avec la carte bleue neutre de l'écran « Position incorrecte » voisin. Relance rapide après un retour au menu : `_open_board_with_retry()` (`core/game_manager_modes/lichess.py`) retente l'ouverture de l'échiquier pendant `_BOARD_OPEN_RETRY_TOTAL_S` (5s, intervalle 1s) si `create_board()` échoue avec « board connection error » — avant, un seul essai immédiat faisait abandonner (sys.exit dans `NicLinkManager.__init__`, driver.py non modifié) sans jamais retenter, alors qu'un essai plus tardif réussissait toujours. Cause probable (non vérifiée avec le matériel) : le plateau Chessnut peut ne pas avoir fini de se réinitialiser côté firmware/USB juste après l'« upload mode » envoyé par `disconnect()`. `hid_backend.py` journalise désormais le résultat (succès/échec, durée, FEN lu) de chaque `connect()`, et son logger est élevé à INFO (`alchess.py::_setup_logging`) pour être visible dans `niclink.log` sans `NICLINK_LOG=DEBUG`. Si l'échiquier reste introuvable malgré les essais, le toast existant « toast.board_not_found » + l'évènement `board_error` restent émis (jamais de retour silencieux au menu).
**Correctif faux refus de nulle (#318)** : `offer_draw` (#316) ne suffisait pas — l'écho du `gameState` de notre propre coup déclenchait quand même « Nulle refusée » avant toute réponse réelle de l'adversaire. `_apply_new_moves()` retourne désormais la couleur du dernier coup appliqué ; `_apply_game_state()` n'évalue le refus que si ce dernier coup est celui de l'adversaire (jamais sur l'écho de notre propre coup). Journal INFO enrichi : `coup envoyé` indique `offre_nulle_jointe`, chaque état reçu journalise coups/statut/`wdraw`/`bdraw` bruts (rien de secret).
**Correctif annulation non demandée (#319)** : `action_queue` (serveur) est globale et partagée par tous les modes ; une action « back_menu » laissée par l'écran de fin de la partie PRÉCÉDENTE (ou par la fenêtre d'attente de la partie en cours de lancement, état « connecting ») y restait en attente, puis était lue dès le premier passage de `LichessGame._process_browser_actions()` de la partie SUIVANTE — avant même le premier événement de flux — et l'annulait à tort (« partie annulée, moins de 2 coups »). `_discard_stale_browser_actions()` (`core/game_manager_modes/lichess.py`) vide désormais cette file juste avant `game.start()` (même geste que `humain.py`/`pedagogique.py`) ; seule une action reçue après ce point peut affecter la partie. Journal : toute annulation/abandon écrit sa raison (« retour au menu demandé par l'utilisateur », « bouton Abandonner demandé par l'utilisateur », ou « autre » si non demandée) — `game.py::_request_resign_or_abort(reason=...)` / `_notify_unexpected_end()`. Point distinct documenté (non corrigé, lecture seule de `driver.py`) : le premier essai d'ouverture de l'échiquier peut échouer même après une poignée de main USB réussie — `NicLinkManager.connect()` ne laisse que 2×`thread_sleep_delay` (0,1s via `board_adapter.py`) pour qu'un premier FEN arrive ; absorbé silencieusement par `_open_board_with_retry()` (#317), sans lien avec l'annulation ci-dessus.

## Conventions
Début de session : `git status`, branche `master`, `TESTS.md`. Tests : `python -m pytest nicsoft/tests -m "not hardware"`. Commits ciblés. USB (ThinkPad X1 Gen 7) : quirk `/etc/modprobe.d/chessnut.conf` = `options usbhid quirks=0x2d80:0x8003:0x40`, udev `autosuspend=-1`, launcher `/usr/bin/python3` (voir `INSTALLATION_ALCHESS.md`).

## Moteurs (`engine_manager.py`)
`find_stockfish/lc0/maia_weights(elo)/rodent()` + `*_available()` ; `server.py` met en cache au démarrage et émet `*_status` ; le front grise ou replie sur le premier disponible.
- **Stockfish** : Linux système/PATH/`engines/stockfish`, Win `engines/stockfish*.exe` ; détection = présence.
- **Maia** : `engines/maia/lc0` et `lc0.exe` + poids `maia-*.pb.gz` (suivis par git).
- **Rodent IV** : Linux `engines/rodent-iv/` ignoré par git (binaire compilé localement, plus un sous-module depuis #260) ; Win `engines/rodent-iv-win/` : 3 fichiers **suivis par git**, téléchargement tout-ou-rien vérifié par SHA-256 (#286). Détection = handshake UCI ; `setoption` Personality→UCI_LimitStrength→UCI_Elo.
