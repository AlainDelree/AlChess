# AlChess — Architecture et invariants généraux

Lire avant toute tâche qui touche à plusieurs modes, à l'infrastructure serveur, ou au câblage frontend/backend.

- **ARC-001** : `core/modes/niclink/utils/engine` n'importent jamais `nicsoft.web` ; ils passent par `core/ihm_port.py` (backend branché au démarrage par `nicsoft.web.alchess`, neutre sinon). Garde : `test_no_web_import.py`.
- `board.move_stack` = source de vérité ; `chess.Board(fen)` l'efface → reconstruire depuis l'historique. Le FEN transmis doit toujours être **complet** (`board.fen()`), jamais la seule disposition des pièces (`board.board_fen()`) — un FEN tronqué remet le trait aux Blancs par défaut et fait calculer un moteur pour le mauvais camp (bug réel, #338). Détail : CHANGELOG.md (#338).
- `on_action` : chaque `sendAction({type:X})` JS a son `elif atype == "X"` correspondant dans `alchess.py` — un handler manquant est ignoré silencieusement.
- i18n : clé ajoutée **simultanément** dans `fr/en/de.json` (`static/i18n/`) ; allemand incertain → valeur anglaise, jamais absente.
- Tout texte externe (PGN, noms, messages serveur, réponses LLM, Lichess) → `esc()` ou `textContent`, jamais brut dans `innerHTML`. Garde : `test_issue303_html_escaping.py`.
- Aucun secret n'est envoyé au navigateur (clé LLM, jeton Lichess) : le serveur ne renvoie qu'un indicateur de présence (+ indice 4 derniers caractères si valeur ≥ 12). Garde : `test_issue304_security.py`.
- Démarrage serveur : ne jamais abaisser le niveau du `file_handler` partagé du root logger sans donner à `werkzeug` son propre handler console (sinon `Running on http://...` disparaît) ; `server.py::start_server()` affiche toujours l'adresse via `print(..., flush=True)`. Détail : CHANGELOG.md (#312).
- Arrêt du processus : un seul chemin de sortie — tout arrêt interne envoie SIGTERM au process lui-même (jamais `os._exit()` depuis un fil daemon), pour toujours traverser `_handle_termination_signal` (`alchess.py`) et ses `atexit` (ModemManager, marqueur d'instance). Jamais deux chemins de sortie concurrents. Détail : CHANGELOG.md (#337).
- **Instance unique** : `alchess.py::main()` appelle `single_instance.resolve_startup()` en premier geste. Marqueur `DATA_DIR/server_instance.json` (pid/port), supprimé à la sortie si le PID correspond encore. Reconnaissance d'un process AlChess : PID vivant **ET** ligne de commande contenant `nicsoft.web` (jamais le seul nom du programme). Partie en cours = `GET /instance_status` sur `_app_state` ∈ `single_instance.BUSY_STATES` ; état non confirmable → refus par précaution. Arrêt toujours par PID exact (jamais par nom). `ALCHESS_SKIP_SINGLE_INSTANCE=1` désactive tout ça pour les serveurs de test. Garde : `test_issue320_single_instance.py`. Détail : CHANGELOG.md (#320,#324).
- **Un seul client socket.io à la fois** : `_app_state`/`event_queue`/`action_queue`/`menu_queue` sont globaux au process serveur, pas par connexion — un test e2e qui ouvre une SECONDE page/onglet vers le serveur de session partagée casse en cascade tous les tests e2e suivants (constaté #369). Un test qui a besoin d'une page fraîche isolée doit lancer son propre serveur dédié (même modèle que `server_url`, conftest.py) plutôt que de se connecter une deuxième fois au serveur de session.
- **Retour au menu / relance de mode** : réinitialiser toute variable d'état résiduelle (JS *et* Python) avant d'autoriser un nouveau lancement — mais sans écraser un choix persistant de l'utilisateur (ex. mode virtuel) par une valeur par défaut codée en dur : réutiliser la variable d'état courante. Joindre (avec timeout) tout thread de l'ancien mode avant de démarrer le nouveau — un thread survivant fausse le lancement suivant. Ne jamais réinitialiser un état de session JS dans un handler `socket.on("connect")` : il s'exécute à chaque reconnexion, pas seulement au chargement de page.
- Toujours émettre l'évènement UI (`send_event`) avant toute I/O disque bloquante (ex. sauvegarde PGN) — l'inverse retarde l'affichage côté navigateur sans bénéfice.
- `index.html` : après toute modification, vérifier l'équilibre des balises (`<div>`/`<button>`…) — une balise fermante manquante a déjà fait hériter silencieusement un écran du `display:none` d'un parent, ou englouti les boutons suivants dans un seul élément cliquable.
- Notation SAN affichée/journalisée : toujours `san_ep()` (`engine/board_utils.py`), jamais `board.san()` directement — seul `san_ep` ajoute le suffixe « e.p. » pour une prise en passant. Violation connue restante (hors flux affiché à l'utilisateur, hors périmètre) : outils d'import/export de livres d'ouvertures (`modes/exercices/*`). Garde (nouvelles occurrences seulement) : `test_issue359_san_ep_guard.py`.
- Exceptions de contrôle de flux (`BackMenuExit`, `ExitNicLink`, `SystemExit`) : un `except Exception` générique ne doit jamais les traiter comme un crash — toujours un `except (BackMenuExit, ExitNicLink, SystemExit): raise`/traitement dédié AVANT lui (ex. `pedagogique.py::Game.run()`, `game_manager_modes/pedagogique.py::_run_pedagogique()`, `modes/exercices/exercices.py::_wait_human_move()`, `modes/humain/human.py::GameWeb._handle_turn()`). Retour au menu du mode humain aligné sur ce schéma (`BackMenuExit` levée par `GameWeb._traiter_abandon()`, capturée dans `game_manager_modes/humain.py::_run_humain()`) — voir CHANGELOG.md (#360). `SystemExit("board connection error")` (`driver.py`) est un second usage délibéré (signal de connexion, pas un arrêt applicatif) : le capturer pour afficher un toast n'est pas une violation de cette règle.
- Tout évènement serveur→navigateur (`send_event`/`emit`/`socketio.emit`) doit avoir un `socket.on`/`socket.once` correspondant dans `app.js`, sinon il est ignoré en silence (bugs passés : bouton « Continuer » des exercices, coup adverse affiché sans FEN). Garde : `test_issue359_event_handler_guard.py`.
- Bouton exigeant l'échiquier physique → attribut `data-needs-board` (+ `data-physical-only` si aucun repli virtuel) : `_applyBoardBadge()` (app.js) (dés)active génériquement tous ces boutons selon l'état courant (`board_ok`/`board_error`/`board_reconnecting`), y compris à une déconnexion en cours de session — jamais de second mécanisme ad hoc par bouton. Détail : CHANGELOG.md (#366).
- `app.js` : tout `socket.on(...)` écrit au premier niveau du script (pas dans une fonction) doit se trouver APRÈS `const socket = io();` — sinon `ReferenceError` (zone morte temporaire) dès le chargement, qui casse toute l'init JS (`#startup-overlay` ne se masque jamais). `.board-warning-banner` : classe de style réutilisable, mais `_applyBoardBadge()` masque génériquement tout élément qui la porte selon `_boardError` seul — un bandeau piloté par un autre état (ex. réseau) doit l'exclure (`:not(#id)`) ou utiliser une classe dédiée. Détail : CHANGELOG.md (#369).
